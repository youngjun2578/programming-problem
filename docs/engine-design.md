# 문제 엔진 설계

NCS 전산직 필기시험 대비용 진단의 문제 엔진 설계다. 코딩테스트처럼 코드를 작성하는 문제가 아니라, **코드·SQL을 읽고 출력값이나 결과를 고르는 5지선다 객관식**이 중심이다.

이 문서는 구조와 규칙을 정한다. 이번 구현 범위는 영역별 대표 유형 4개씩(★)이며, 나머지 유형은 다음 작업에서 같은 구조로 확장한다.

## 1. 영역과 언어 선택

| 영역 | id | 내용 |
|---|---|---|
| 프로그래밍 | `programming` | 사용자가 고른 언어(C, C++, Python, Java) 하나로 된 코드를 읽고 출력 결과를 고른다 |
| SQL | `sql` | 표와 SQL 문을 읽고 조회 결과(행 수·값)를 고른다 |

- 사용자는 진단을 시작할 때 프로그래밍 언어를 하나 고른다. 세트는 **"선택한 언어의 프로그래밍 + SQL"** 두 영역으로 만든다.
- SQL만 보는 옵션은 이번에는 만들지 않는다.
- 언어 id: `c`, `cpp`, `python`, `java` (`shared/languages.ts` 한 곳에서 정의).

### 언어 선택이 이어지는 곳
| 단계 | 반영 방식 |
|---|---|
| 세션 요청 | `POST /api/session` 본문 `{ "lang": "python", "level"?: ... }`. `lang`이 없거나 모르는 값이면 400 |
| 토큰 | 본문 `{ v: 2, s, iat, g: 언어, l?: "adv" }`. 서명되어 있어 언어를 바꿔 채점받을 수 없다. 토큰 버전을 2로 올려 언어가 없는 이전 토큰은 받지 않는다 |
| 생성 시드 | `generationSeed(secret, 공개 시드, level, lang)`의 이름표에 언어를 넣는다(`gen:v2:{lang}:{seed}`, 심화는 `gen:v2:adv:{lang}:{seed}`). 같은 공개 시드라도 언어마다 다른 문항이 나온다 |
| 채점 | 요청 본문의 언어는 읽지 않고 토큰의 `g`로만 문항을 다시 만든다 |
| 결과 리포트 | `meta.language: { id, name }`. 화면 머리말에 언어를 표시한다 |
| 응답 | 프로그래밍 문항의 코드는 선택한 언어로만 렌더링한다. 다른 언어 코드가 섞이지 않는지 `scripts/api-test.ts`가 확인한다 |

## 2. 문제 형식

- 보기 5개 객관식. 정답은 정확히 하나.
- 프로그래밍 문항의 출력은 **한 번에 정수 하나를 한 줄로** 출력한다(C `printf("%d\n", x)`, C++ `std::cout << x << "\n"`, Java `System.out.println(x)`, Python `print(x)`). 줄바꿈·공백·괄호 같은 출력 형식으로 헷갈리게 하지 않는다. 출력이 여러 줄이면 보기도 줄 단위로 보여 준다.
- 출력은 0 이상의 정수만 쓴다(음수 표기, 소수점 표기 차이를 피한다). 출력 줄 수는 6줄 이하.
- SQL 문항의 답은 결과 행 수(`n개`) 또는 결과 값 하나(정수)다.
- 오답 보기는 **흔한 실수를 모델에 적용해 다시 계산한 값**이다(아래 4절). 실수로 만든 서로 다른 오답이 4개 이상 나오도록, 모자라면 템플릿이 숫자를 다시 뽑는다(`pickVariant`). 그래도 모자랄 때만 정답 근처 값으로 채운다("계산 실수").

## 3. 난이도

기존 `server/levels.ts`의 수준(기본 `basic` / 심화 `advanced`, 심화는 서버 스위치 `ADVANCED_LEVEL_ENABLED`가 켜졌을 때만)을 그대로 쓴다. 템플릿은 난이도 1~3을 모두 만들 수 있고, 세트가 문항 자리마다 난이도를 정한다.

| 난이도 | 코드 길이(본문) | 변수 | 개념 수 | 예 |
|---|---|---|---|---|
| 1 | 8줄 안팎 | 1~2개 | 1개 | 반복 하나로 누적 |
| 2 | 12줄 안팎 | 2~3개 | 2개 | 반복 + 조건/continue |
| 3 | 16줄 안팎 | 3~4개 | 3개 | 반복 + 조건 + break, 재귀 + 기저 조건 |

| 수준 | 영역 안 문항 자리별 난이도(3문항일 때) |
|---|---|
| 기본 | 1, 1, 2 |
| 심화 | 2, 2, 3 |

SQL은 같은 표를 조건 수(1~3개), 연산자 종류, 표의 NULL·조인 상대 수로 난이도를 나눈다.

## 4. 정답 계산 구조

### 프로그래밍: 프로그램 모델 → 네 언어 렌더러 → 참조 평가기
```
시드 → 템플릿 → 프로그램 모델(변수, 반복, 조건, 배열, 함수 구조)
                    ├─ 렌더러(C / C++ / Java / Python) → 화면에 보이는 코드
                    ├─ 참조 평가기(TypeScript)         → 정답 출력
                    └─ 실수 변형(mutation) → 평가기    → 오답 출력 + 실수 유형
```
- 모델: `server/engine/program/model.ts`. 정수 변수, 정수 배열, 산술·비교·논리식, `for`(증가·감소), `while`, `if / else if / else`, `switch`(C·C++·Java 전용), `break`, `continue`, 함수와 재귀, `print`.
- 렌더러: `server/engine/program/render.ts`. 한 모델을 네 언어 문법으로 바꾼다. Python의 `for`는 `range(...)`, 나눗셈은 `//`, `&&`·`||`·`!`는 `and`·`or`·`not`, 배열 길이는 C·C++이 숫자 그대로, Java `a.length`, Python `len(a)`.
- 참조 평가기: `server/engine/program/eval.ts`. 모델을 직접 해석한다. **사용자 코드나 렌더링한 코드를 실행하지 않는다.** 실행 단계 수(무한 반복 방지), 값 범위(±2³¹ 미만), 출력 줄 수를 제한하고, 넘으면 예외를 던져 템플릿이 다시 뽑게 한다.
- 실수 변형: `server/engine/program/mutate.ts`. 모델의 일부를 흔한 실수 쪽으로 바꾼 사본을 만든다. 변형한 모델을 평가기로 실행한 출력이 오답 보기다.

### SQL: 표 생성기 → 미니 평가기
- 표 생성기(`server/engine/sql/tables.ts`): 시드로 행 5~12개의 작은 표를 만든다. 필요한 유형만 NULL을 넣는다.
- 질의 모델(`model.ts`)과 렌더러(`render.ts`): `SELECT … FROM … [INNER|LEFT JOIN … ON …] [WHERE …] [GROUP BY …] [HAVING …]`.
- 미니 평가기(`eval.ts`): 필터, 집계, 그룹, 조인, NULL의 3값 논리를 TypeScript로 계산한다. 외부 DB 라이브러리를 쓰지 않는다.
- 오답은 질의 모델을 실수 쪽으로 바꿔(AND↔OR, `>=`↔`>`, INNER↔LEFT, WHERE 조건 빠뜨림 등) 다시 평가한 값이다.

### 서버에서 하지 않는 것
- 서버 런타임(`api/`, `server/`)은 어떤 코드나 질의도 실제로 실행하지 않는다. `child_process`, `eval`, `new Function`을 쓰지 않는다.
- 실제 컴파일러·인터프리터로 확인하는 일은 개발용 스크립트 `scripts/crosscheck.ts`(`npm run check:exec`)만 한다. build·test·서버 코드에 넣지 않는다.

## 5. 금지 규칙(정의되지 않은 동작, 언어 차이)

### 모든 언어 공통 템플릿
- 음수 나눗셈·음수 나머지를 쓰지 않는다(C·Java는 0 쪽으로 자르고 Python은 내림). 평가기는 나눗셈·나머지의 피연산자가 음수거나 0으로 나누면 예외를 던진다.
- 출력은 0 이상의 정수. 불리언·실수·문자열을 출력하지 않는다.
- 반복 변수를 반복 본문에서 바꾸지 않고, 반복이 끝난 뒤 반복 변수를 읽지 않는다(Python `range`와 C 계열 `for`의 차이).
- `while` 안의 `continue`는 반복 변수를 바꾼 뒤에만 둔다(무한 반복 방지).
- 정수는 작은 범위(대개 0~1,000)에서만 쓴다. 평가기가 ±2³¹ 범위를 넘으면 그 모델을 버린다.

### C·C++
- 초기화하지 않은 변수, 부호 있는 정수 오버플로, 평가 순서가 불명확한 식(`i++ + ++i`, `a[i] = i++` 등), 배열 범위 밖 접근을 쓰지 않는다. 평가기는 범위 밖 인덱스에서 예외를 던진다.
- 증감 연산자(`i++`)는 문장으로만 쓴다(식 안에서 쓰지 않는다).

### 언어 전용 템플릿
- Python 슬라이싱, 정수 나눗셈 `//`의 음수 동작, Java 참조 전달, C 포인터처럼 언어마다 결과가 다른 동작은 **언어 전용 템플릿**으로 따로 만들고 그 언어에서만 출제한다(템플릿의 `langs` 목록).
- 같은 템플릿 안에서도 문법이 없는 언어에는 그 변형을 쓰지 않는다(예: Python에는 `switch`가 없으므로 P3의 switch 변형은 C·C++·Java에서만).

### SQL
- 표준 SQL의 공통 부분만 쓴다. `LIMIT`, `ROWNUM`, `TOP`, 날짜·문자열 함수 같은 방언 문법은 쓰지 않는다.
- `LIKE`는 한글 값과 `%` 접두·접미 패턴만 쓴다(영문 대소문자 구분이 DB마다 다르다).
- `AVG`는 결과가 정수로 나누어떨어지는 표만 쓴다(정수 AVG를 자르는 DB와 실수로 내는 DB가 있다).
- `ORDER BY`를 쓰는 유형은 정렬 기준에 동률이 생기지 않게 표를 만든다.
- 동률·NULL 때문에 정답이 모호해지는 표는 생성기에서 버린다.

## 6. 세트 구성

- 영역 안에서 서로 다른 유형만 뽑는 기존 규칙(`server/engine/set.ts`)을 유지한다.
- 영역별 문항 수 `PER_AREA = 3`, 영역 2개 → **세트 6문항**. 영역별 유형이 4개라 매번 4개 가운데 3개가 나온다.
- 프로그래밍 영역은 선택한 언어로 출제할 수 있는 유형만 후보로 쓴다.

## 7. 유형표

★: 이번에 구현한 대표 유형. 난이도는 1~3 가운데 만들 수 있는 범위.

### 프로그래밍
| 유형 | 내용 | 가용 언어 | 난이도 | 오답 생성 규칙 | 위험 요소(언어별 차이) |
|---|---|---|---|---|---|
| P1 ★ | 반복문 출력·누적 (for/while, continue/break) | C, C++, Python, Java | 1~3 | 끝값 포함 여부 뒤집기, 시작값 한 칸 밀기, continue↔break 바꾸기, 조건 빼기, 누적(+=)을 대입(=)으로, 출력 위치를 반복 안/밖으로 | Python `range` 끝값 미포함, 반복 변수 사후 사용 금지, while+continue 무한 반복 |
| P2 | 중첩 반복문 출력 횟수·별 찍기 | 4개 언어 | 1~3 | 안쪽 범위를 바깥 변수와 무관하게 봄, 경계 한 칸 차이 | 별 찍기는 출력 형식(공백) 혼동이 커서 "출력 줄 수·별 개수"로만 묻는다 |
| P3 ★ | 조건 분기 (if/else if, switch의 break 유무) | 4개 언어 (Python은 if/elif만) | 1~3 | `>=`↔`>` 경계 뒤집기, else if를 독립 if로 봄, 조건 순서 무시, switch fall-through 무시·default 실행 | Python에 switch 없음(3.10 match는 쓰지 않음), C 계열 switch fall-through |
| P4 ★ | 배열/리스트 순회 (합, 최댓값, 역순, 인덱스) | 4개 언어 | 1~3 | 인덱스 시작 0↔1, 끝 인덱스 한 칸 차이, 최댓값 비교 `>`↔`>=`(같은 값의 인덱스), 값과 인덱스 혼동 | 배열 길이 표현(C 숫자, Java `.length`, Python `len`), 범위 밖 접근 금지 |
| P5 | 2차원 배열 (대각합, 전치) | 4개 언어 | 2~3 | 행·열 뒤바꿈, 반대 대각선 | C 2차원 초기화 문법, Python 리스트 복제 함정(`[[0]*n]*n`)은 쓰지 않음 |
| P6 | 문자열 처리 (길이, 인덱스, 문자 개수, 부분 문자열) | 4개 언어 | 1~3 | 길이 한 칸 차이(C 널 문자), 부분 문자열 끝 포함 여부 | C `strlen` vs 배열 크기, Java `substring` 끝 미포함, Python 슬라이싱은 Python 전용 템플릿으로 |
| P7 ★ | 함수 호출과 반환값, 재귀(팩토리얼, 피보나치) | 4개 언어 | 1~3 | 기저 조건 값·경계 바꾸기, 인자 n↔n−1, 반환값 대신 인자 출력, 호출 순서 혼동 | 재귀 깊이는 작게(20 이하), 큰 수 오버플로 금지 |
| P8 | 연산자 (정수 나눗셈, 나머지, 비트 연산, 우선순위) | 4개 언어 | 1~3 | 정수 나눗셈을 실수로 계산, 우선순위 무시(왼쪽부터 계산) | 음수 나눗셈·나머지 금지, Python `/`는 실수(`//`로 렌더링), 비트 연산 우선순위가 언어마다 같은지 확인 |
| P9 | 값 전달 vs 참조 전달 | 언어 전용 (C 포인터, C++ 참조, Java 배열/객체, Python 가변 객체) | 2~3 | 값 전달로 봄 ↔ 참조 전달로 봄 | 언어마다 의미가 달라 반드시 전용 템플릿 |
| P10 | 포인터 연산 | C, C++ 전용 | 2~3 | 주소 한 칸 차이, `*p++` 의미 혼동 | 정의되지 않은 동작(범위 밖 포인터 역참조) 금지 |
| P11 | 클래스·상속·오버라이딩·생성자 호출 순서 | C++, Java, Python 전용 | 2~3 | 부모/자식 메서드 혼동, 생성자 순서 뒤집기 | C++ virtual 유무, Python `super()` 호출 여부 |
| P12 | 스택/큐 동작 결과 (push/pop 시퀀스) | 4개 언어 | 1~2 | 스택↔큐 혼동, 마지막 pop 빠뜨림 | 표준 라이브러리 이름이 언어마다 다름(C는 배열로 구현) |
| P13 | 변수 범위, static/전역 | C, C++, Java, Python(global) | 2~3 | 지역 변수 가림 무시, static 초기화 매번으로 봄 | Python은 `global` 선언 규칙이 다름 → 전용 변형 |
| P14 | 정렬(버블 1패스 후 상태), 이진탐색 비교 횟수 | 4개 언어 | 2~3 | 패스 수 한 번 차이, 비교 횟수 경계 | 중간 인덱스 계산 `(lo + hi) / 2`는 음수 없음 |

### SQL
| 유형 | 내용 | 난이도 | 오답 생성 규칙 | 위험 요소(DB별 차이) |
|---|---|---|---|---|
| S1 ★ | SELECT + WHERE 결과 행 수 (AND/OR/NOT, IN, BETWEEN, LIKE) | 1~3 | AND↔OR, NOT 빼기, BETWEEN 끝값 제외, IN 목록 하나 빼기, LIKE 접두↔포함, 조건 하나 빼기, 전체 행 수 | LIKE 대소문자(한글 값만 사용) |
| S2 ★ | 집계 함수 결과 값 (COUNT/SUM/AVG/MAX/MIN) | 1~3 | COUNT(*)↔COUNT(열)(NULL), AVG 분모에 NULL 포함, WHERE 무시, MAX↔MIN, SUM↔AVG | AVG 정수 자름(나누어떨어지는 표만), NULL 무시 규칙 |
| S3 | ORDER BY 후 n번째 행 값 | 1~3 | 오름↔내림, n번째 한 칸 차이 | 동률 금지, NULL 정렬 위치가 DB마다 다름 → 정렬 열에 NULL 금지 |
| S4 ★ | GROUP BY + HAVING 결과 행 수·값 | 1~3 | HAVING `>=`↔`>`, HAVING 무시, WHERE와 HAVING 순서 혼동, 그룹 수 대신 행 수 | 선택 열은 GROUP BY 열과 집계만(표준 SQL) |
| S5 ★ | INNER JOIN / LEFT JOIN 결과 행 수 | 1~3 | INNER↔LEFT, 왼쪽 표 행 수, 오른쪽 표 행 수, 일치 키 중복 무시 | 조인 키 NULL은 어느 행과도 일치하지 않음 |
| S6 | 서브쿼리 (IN, 스칼라) | 2~3 | 서브쿼리 결과를 한 행으로 봄, NOT IN과 NULL | NOT IN + NULL은 결과가 비는 함정 → 따로 다룸 |
| S7 | NULL 처리 (COUNT(*) vs COUNT(열), = NULL 함정) | 1~3 | `= NULL`을 참으로 봄, COUNT(열)에 NULL 포함 | `= NULL`은 항상 UNKNOWN |
| S8 | DISTINCT, UNION / UNION ALL 행 수 | 1~2 | UNION↔UNION ALL, DISTINCT 무시 | NULL끼리는 DISTINCT에서 같은 값 |
| S9 | INSERT/UPDATE/DELETE 후 SELECT 결과 | 2~3 | WHERE 없는 UPDATE 범위, 순서 혼동 | 자동 커밋·트랜잭션은 다루지 않음 |
| S10 | 제약조건 위반 여부 (PRIMARY KEY, FOREIGN KEY, NOT NULL) | 1~2 | 위반 아닌 것을 위반으로 봄 | SQLite는 FOREIGN KEY 검사가 기본으로 꺼져 있음 → 교차 검증에서 켜야 함 |
