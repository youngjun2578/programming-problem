## 1. 공식 문서 확인 여부: **공식 문서 확인 못 함**
- 확인하려던 문서: Sign in with Google 브랜딩 가이드라인. 주소는 `https://developers.google.com/identity/branding-guidelines`로 알고 있지만, 열어 보지 못했으므로 주소가 맞는지도 확인하지 못했습니다.
- 작성 환경의 네트워크 정책이 `developers.google.com` 접속을 막아 열 수 없었습니다(2026-10-07).
- 그래서 이 문서에는 구글 규정을 적지 않았습니다(기억으로 쓰지 않음). 아래 2·3절은 **현재 코드의 사실만** 정리한 것입니다. 공식 문서와 대조하는 일은 영준님이 직접 해 주세요.

## 3. 로고(G) 사실 확인
- **파일이 아닙니다.** `monetization.ts`의 `GOOGLE_LOGO` 상수에 인라인 SVG로 들어 있습니다(207~213행). 저장소에 로고 이미지 파일(`public/` 등)은 없습니다.
- **출처를 확인할 수 없습니다.**
  - 이 SVG는 커밋 `ffe2762`(2026-10-05, "로그인 창·내 계정 창 디자인 정리")에서 경로 데이터를 직접 코드에 적어 넣은 것입니다.
  - 커밋 메시지에는 "공식 4색 G 로고 인라인 SVG"라고 적혀 있지만, 구글 배포 자산을 내려받은 기록이나 원본 파일은 없습니다.
  - 그래서 "공식 자산을 그대로 쓴 것"인지, "공식 모양을 따라 직접 그린 것"인지는 **확인 못 함**입니다. 공식 자산 파일과 경로 데이터를 직접 비교해야 합니다.
- **색:** 4색 `#EA4335`(빨강), `#4285F4`(파랑), `#FBBC05`(노랑), `#34A853`(초록)입니다. 어두운 화면에서도 색을 바꾸지 않습니다(CSS에서 로고 색을 건드리는 규칙 없음).
- **비율:** `viewBox="0 0 48 48"`이고 20×20px로 그립니다. 가로세로 비율이 1:1 그대로라 늘이거나 눌리지 않습니다.
- **변형:** 회전·잘라내기·테두리·그림자 같은 변형 규칙은 없습니다. 코드 주석은 "색과 모양을 바꾸지 않는다"입니다.

## 4. 차이로 보이는 점
공식 문서를 열지 못해 공식 규정과 비교하지 못했습니다. 아래는 공식 문서와 대조할 때 **특히 볼 곳**입니다. 차이로 확정한 것이 아닙니다.
1. 문구 "Google로 계속하기"가 공식 한국어 문구와 글자 하나까지 같은지(띄어쓰기, "Google" 영문 표기 포함).
2. 로고·글자를 가운데 정렬한 배치(넓은 버튼에서 로고가 왼쪽 끝에 붙지 않음)가 허용되는지.
3. 글꼴: Google Sans·Roboto를 불러오지 않아, 대부분의 기기에서 사이트 글꼴로 보입니다.
4. 높이 44px, 모서리 4px, 좌우 여백 12px, 로고–글자 간격 10px, 로고 20px이 공식 치수와 맞는지.
5. 밝은·어두운 화면 색 6개(바탕·테두리·글자)가 공식 테마 색과 같은지.
6. 비활성 상태를 투명도(0.6)로만 표시하는 방식, 마우스 올림 그림자, 포커스 바깥선 색(사이트 색)이 허용되는지.
7. 로고 SVG 경로가 공식 자산과 같은지(3절).

## 5. 구글 OAuth 동의 화면·앱 게시 관련 사실 (저장소에서 알 수 있는 것)
| 항목 | 저장소에서 알 수 있는 사실 |
|---|---|
| 서비스 이름 | 사이트 이름 "NCS 수리능력 진단"(페이지 제목, `og:site_name`) |
| 홈페이지 주소 | 빌드 값 `VITE_SITE_URL`. 저장소 `.env`에는 자리 표시(example.com)만 있고, 운영 값은 Vercel 환경 변수에 있음(확인 못 함) |
| 개인정보처리방침 주소 | `/privacy/` 페이지가 있음 → `VITE_SITE_URL` + `/privacy/` |
| 이용 약관 주소 | main에는 약관 페이지가 없음(초안은 가지 `terms-draft`, 결제 켜진 빌드에서만) |
| 지원·문의 메일 | 빌드 값 `VITE_CONTACT_EMAIL`(값은 Vercel에 있음, 확인 못 함) |
| 로그인 방식 | Supabase Auth `signInWithOAuth({ provider: 'google' })`. 구글 OAuth 클라이언트는 Supabase에 등록하는 구조 |
| 요청 범위(scopes) | 코드에서 `scopes`를 지정하지 않음 → Supabase 기본값을 씀. 기본값이 무엇인지는 확인 못 함 |
| 로그인 뒤 돌아오는 주소 | `/diagnosis/`, `/diagnosis/?auth=purchase`, 머리말 로그인 버튼을 누른 그 페이지 경로(사이트의 모든 페이지) |
| 구글 쪽 리디렉션 URI | 코드가 직접 정하지 않음. Supabase 프로젝트의 콜백 주소(`https://<프로젝트>.supabase.co/auth/v1/callback`)가 쓰이는 구조 |
| 사이트가 저장하는 정보 | 계정 ID, 이용권 상태(구매 여부·구매 시각). 인증 서비스는 동의 항목(이메일·이름·프로필 사진 주소 등)을 보관할 수 있음(개인정보처리방침 문구) |
| 앱 로고 | 사이트 아이콘 `public/favicon.svg`, 공유 이미지 `public/og.png`. 동의 화면용 로고는 따로 없음 |

## 6. 영준님이 Google Cloud Console에서 확인할 항목
1. OAuth 동의 화면의 게시 상태: 테스트인지 프로덕션인지. 테스트면 등록한 시험 사용자만 로그인됩니다.
2. 앱 이름과 사이트 이름("NCS 수리능력 진단")이 일치하는지. 앱 이름에 "Google" 등 다른 상표를 쓰지 않았는지.
3. 사용자 지원 이메일, 개발자 연락처 이메일.
4. 앱 홈페이지 주소, 개인정보처리방침 주소(`…/privacy/`), 서비스 약관 주소(약관 공개 전이면 비워 둘지).
5. 승인된 도메인: 운영 도메인과 Supabase 도메인이 필요한지.
6. 요청 범위가 로그인에 필요한 기본 범위만인지. 민감·제한 범위가 없는지.
7. 앱 로고를 올릴지. 올리면 확인 절차가 생기는지.
8. OAuth 클라이언트(웹)의 승인된 리디렉션 URI에 Supabase 콜백 주소가 있는지. 승인된 JavaScript 원본이 필요한지.
9. 브랜드 확인(인증) 필요 여부와 진행 상태.
10. Supabase 대시보드: Google 공급자 켜짐, 클라이언트 ID·시크릿 입력, Site URL·Redirect URLs에 5절의 복귀 주소가 모두 들어가는지.
